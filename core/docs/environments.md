# מפת הסביבות

> **מה יש כאן:** כל סביבה של הפרויקט: איפה היא רצה, מה פורס אליה, אילו משתנים היא קוראת, מי רשאי לשנות, ואיך בודקים
> שהיא חיה.
> **מה אין כאן:** ⛔ **אף ערך של משתנה או של סוד.** רק שמות (`docs/engineering-operating-model.md` §8.3–8.4).
> **למה זה חשוב:** env אינו בגיט, ולכן המסמך הזה הוא ה-version control שלו. שינוי קונפיגורציה בלי שורה ב-§5 משאיר את
> המשימה לא גמורה (DoD סעיף 6).
> **ברירת המחדל הזהירה:** עד ש-§2 מלא, כל push נחשב deploy.

⏳ למלא: תאריך העדכון האחרון והבדיקה שאימתה את המפה (קריאה של הקוד, של קונפיגורציית הפריסה ושל ה-`.env.example`).

---

## 1. הסביבות

| | מקומית | בדיקות מבודדות | staging / preview | ייצור |
| :--- | :--- | :--- | :--- | :--- |
| **כתובת** | ⏳ למלא | אין: חבילת הבדיקה מרימה ומורידה אותה | ⏳ למלא / אין | ⏳ למלא |
| **מה פורס אליה** | הרצה ידנית (`docs/runbooks/local-setup.md`) | חבילת הבדיקה | ⏳ למלא: push לענף? | ⏳ למלא: push ל-`main` = deploy? |
| **נתונים** | ⏳ למלא: ריק / seed מקומי | seed מבודד שנמחק בסוף הריצה | ⏳ למלא: נתוני בדיקה בלבד | אמיתיים. ⛔ אין כתיבה ידנית בלי אישור |
| **ספקים חיצוניים** | Mock | Mock | ⏳ למלא: Mock / test mode | רק ספק שאושר ביומן. כל השאר Mock |
| **מי רשאי לשנות** | כל מפתח | — | ⏳ למלא | ⏳ למלא: בעל הפרויקט / האחראי הטכני |
| **בדיקת חיים (health)** | ⏳ למלא | — | ⏳ למלא | ⏳ למלא |
| **סוד חסר** | ברירת מחדל מקומית מותרת | ברירת מחדל של הבדיקה | ⏳ למלא | השרת נכשל בעלייה ולא נופל לברירת מחדל |
| **לוגים** | stdout | stdout של החבילה | ⏳ למלא | ⏳ למלא: איפה, ולכמה זמן נשמרים |

- **המשתנה שמגדיר את הסביבה** צריך להיות אחד ומפורש, לדוגמה `APP_ENV`. לא מסיקים "אני בייצור" ממשתנה שהפלטפורמה מגדירה.
- ⏳ למלא: סביבה נוספת (סביבת ניסוי, עותק לצוות, הדגמה) מקבלת עמודה משלה.

## 2. כלל הפריסה — לכל מאגר ולכל ענף

| מאגר | ענף | push = deploy? | לאן | מי מאשר (לפי רמת העצמאות ב-`AGENTS.md`) | נקודת חזרה |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ⏳ למלא | | | | | |

- push שהוא deploy דורש DoD מלא (`docs/engineering-operating-model.md` §9). ברמות `strict` ו-`balanced` הוא דורש גם אישור.
- "תיעוד בלבד" במאגר שפורס הוא עדיין פריסה.
- runbook השחרור והחזרה: `docs/runbooks/release.md`.

## 3. המשתנים — שמות בלבד

| משתנה | שירות | מקומית | staging | ייצור | איפה מוגדר | מי מגדיר | סוד? | ברירת המחדל בקוד שונה מהייצור? |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| ⏳ למלא (לדוגמה: `APP_ENV`) | | ✓ | ✓ | ✓ | `.env` / פלטפורמת הפריסה | | לא | |

- בעמודות הסביבה כותבים ✓ (מוגדר) או — (לא מוגדר). **לא כותבים ערך**, גם לא של משתנה שאינו סוד.
- **איפה מוגדר:** `.env` מקומי (ב-gitignore) · env בפלטפורמת הפריסה · קובץ קונפיגורציה בגיט · נוצר אוטומטית בפלטפורמה ·
  מועתק משירות אחר.
- ברירת מחדל בקוד ששונה מהערך בייצור מסומנת ⚠️. זו מלכודת שמסתירה באגים מקומית.

## 4. מפת הסודות — שמות בלבד

**איפה ערך סודי יכול לשבת** (`docs/engineering-operating-model.md` §8.3):

| # | המקום | מי רואה |
| :--- | :--- | :--- |
| 1 | env בפלטפורמת הפריסה | ⏳ למלא |
| 2 | `.env` מקומי בכל מאגר. ⏳ למלא: אומת שהוא ב-gitignore בתאריך … | המחשב של המפתח |
| 3 | תיקיית secrets מקומית מחוץ לגיט | ⏳ למלא |

| סוד (שם) | סוג | מה הוא פותח | איפה הוא יושב | מי מגדיר | החלפה |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ⏳ למלא | | | | | |

- **סוג:** מפתח בין שרתים · מלח או pepper · פרט כניסה לספק חיצוני · קוד גישה לאדם · מזהה שאינו סוד.
- **החלפה:** ✅ בטוחה · ⚠️ דורשת צעד נוסף (כתוב איזה) · ⛔ אסור להחליף, כי נתונים קיימים תלויים בו.
- ה-AI אינו קורא, מדפיס או מקליד ערך סודי. בעל הפרויקט מזין סודות בעצמו.
- כשמחליפים סוד, מעדכנים את הטבלה אם המקום או הנוהל השתנו, ורושמים שורה ב-§5.

## 5. יומן שינויי קונפיגורציה

| תאריך | משתנה (שם) | שירות / סביבה | מה השתנה | מי | הבדיקה שהוכיחה | שורת יומן |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| ⏳ | | | | | | |

- **"מה השתנה" בלי ערך:** נוסף · הוחלף · הוסר · הופעל · כובה.
- כל שינוי ב-env, בקונפיגורציית הפריסה או בהגדרה שמשנה התנהגות במסך ניהול מקבל שורה כאן ושורה ב-`docs/decisions-log.md`.
- השורות לא נמחקות. תיקון נכתב בשורה חדשה.

## 6. בדיקת סחיפה

שלושה מקומות צריכים להסכים:
1. מה שהקוד קורא מהסביבה (לדוגמה `process.env.X` או `os.environ["X"]`).
2. מה שמוגדר בפלטפורמת הפריסה ובקובץ קונפיגורציית הפריסה.
3. מה שכתוב ב-§3.

⏳ למלא: הפקודה שמשווה ביניהם, או "ידני" עם תאריך הבדיקה האחרונה.

**עמימויות נפוצות שהמפה צריכה לסגור:**
- התנהגות שתלויה ב"האם אני רץ בפלטפורמה X" במקום במשתנה סביבה מפורש.
- סדר קדימות שלא מתועד, למשל קובץ › סביבה › ברירת מחדל, כשהקובץ גובר על הסביבה בלי שאיש יודע.
- ברירות מחדל בקוד ששונות מהייצור (§3).
- אותה הגדרה שמוגדרת בשני מקומות.
- תקרות ומונים בזיכרון התהליך, שמתאפסים בכל אתחול. "30 ביום" כזה אינו 30 ביום.
- קובץ על דיסק זמני בפלטפורמה, שנמחק בכל פריסה או הירדמות.
