# docs/architecture — איך המערכת בנויה

> כאן נמצאים המסמכים שמתארים את המערכת **כפי שהיא**: רכיבים, גבולות, זרימות וחוזים.
> למה החלטנו כך, מופיע ב-`docs/decisions-log.md` וב-`docs/adr/`. איך מריצים, מופיע ב-`docs/runbooks/`.

## מה נכנס

| מסמך | מה הוא עונה |
| :--- | :--- |
| `overview.md` | אילו רכיבים יש, מה כל אחד עושה, ומי מדבר עם מי |
| `request-response-flow.md` | מה קורה לבקשה אחת מהדפדפן ועד התשובה (ראשון לכתיבה, ראו למטה) |
| `data-ownership-and-storage.md` | באיזה מאגר או שירות יושב כל סוג נתון, מי הבעלים, גיבוי ומחיקה. מודל הנתונים עצמו (ישויות ושדות) — רק ב-`docs/data/data-model.md` |
| `security-and-threat-model.md` | אזורי אמון, זהויות, הרשאות, איומים, ואיך בודקים אותם |
| `api-contract.md` | חוזה ה-API: נקודות קצה, קלט ופלט, קודי שגיאה, והחוזים מול מערכות חיצוניות |
| `rag-stage-1.md` | רק כשיש צורך ב-RAG (`docs/engineering-operating-model.md` §8.5) |

## מה לא נכנס

- החלטות ונימוקים: הם ב-`docs/decisions-log.md`, וב-`docs/adr/` כשההחלטה מעל הסף.
- פקודות והוראות הרצה: הן ב-`docs/runbooks/`.
- ערכים של משתנים וסודות: הם לא נכתבים בשום מסמך. השמות נמצאים ב-`docs/environments.md`.

## הכללים

- **המסמך מתאר את מה שקיים.** תכנון שעוד לא מומש מסומן בכותרת "מתוכנן", עם קישור לשורת היומן.
- **מסמך שסותר את הקוד הוא באג.** מי שמשנה זרימה או חוזה מעדכן את המסמך באותו commit (DoD סעיף 5).
- **כל מסמך נכתב ממקור:** קריאה של הקוד, הרצה או חוזה. כל טענה מפנה לקובץ או לפקודה. מה שלא ידוע נכתב ב-`docs/open-questions.md`, ולא מומצא.
- **ספק חיצוני** מופיע עם המצב שלו: Mock או אמיתי, ושורת היומן שאישרה אותו.

## המסמך הראשון: `request-response-flow.md`

זה הפריט הראשון בסדר העדיפויות (`docs/engineering-operating-model.md` §10). מתחילים ממנו כי בלעדיו אי אפשר לדבג, לרשום לוגים
או לבדוק שחזור. השלד:

1. **בקשה אחת מייצגת:** הפעולה המרכזית של המוצר. ⏳ למלא
2. **השחקנים:** דפדפן או לקוח, שרת הקצה, שירותים פנימיים, מאגר הנתונים, ספקים חיצוניים.
3. **הצעדים:** טבלה `| # | מאיפה | לאן | נתיב או פעולה | אימות והרשאה | נתונים שנקראים או נכתבים | ספק חיצוני (Mock / אמיתי) |`.
4. **מזהה הבקשה:** איפה נוצר `X-Request-Id`, ואיך הוא עובר בין השירותים (`docs/engineering-operating-model.md` §8.2).
5. **מסלולי שגיאה:** timeout, ספק שנפל, הרשאה חסרה. מה המשתמש רואה בכל אחד מהם.
6. **מה נרשם בלוג בכל צעד**, ומה **אסור** שיירשם.
7. **איך בודקים את הזרימה:** הפקודה ב-`docs/runbooks/local-setup.md` §3.
8. **מה לא מתועד עדיין.**
